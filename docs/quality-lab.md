# 聊天实验室

管理台的聊天实验室复用 `scripts/quality_eval` 的普通/YAML 实际回复入口。每个候选由独立 Python 子进程执行，使用独立数据库、空外部工具注册表和捕获发送器。不会读取生产历史或记忆，也不会发送真实消息；导入的历史与记忆快照是唯一可用资料。媒体与外部工具案例仍使用离线评测入口，网页明确拒绝不支持的字段。

## 工作流

1. 从真实失败对话选取必要上下文，替换真实身份与隐私，检查正文和人格快照，勾选已经脱敏。建议开发集 30 段、保留集 20 段；系统不会用自动生成样例冒充真实语料。
2. 导入案例，选择当前配置中的模型路由、案例和本次请求上限，预览后显式运行。上限包含规划、生成和审阅请求；默认没有继承历史评测的调用授权。
3. 实验为每案例生成 A（当前策略）、B（表达偏好）、C（表达偏好与长度软目标）。模型、人格、上下文和行为配置保持一致，每候选的状态副本互不影响。
4. 对三组随机顺序的两两候选进行五维人工评分，可选择胜、平或两者都差。隐藏版本与耗时，全部完成后才能揭盲；揭盲后评分锁定。
5. 报告保留失败、模型请求数、Provider 返回的 Token、耗时、长度观测及重复表达指标。重复指标只是诊断，不会删改回复；没有 Token 信息时显示未知，不推算。

## 约束与回退

- 默认生产仍是 A。B/C 只在隔离评测子进程的 ContextVar 作用域生效，不能直接成为生产默认。自然度结论需人工复核与保留集；功能测试通过不证明质量提升。
- C 的群聊插话、明确提及、私聊软目标分别为 20–80、40–180、80–400 字，不设最低字数，允许超出。管理员既有全局硬上限仍保留；证据交付和独立资源预算不改变。
- 当前网页支持 OpenAI 接口与明确 bearer 认证的 Gemini 自定义接口。官方 Gemini 自动认证、CLI 和其它尚无单请求预算保证的路线不会列出；沿用当前模型，不自动换模型。
- 预算通过共享 SQLite 预留，单次调用关闭重试、协议回退和内建搜索。中止会结束子进程；重启标记中断，不恢复或重放未知请求。
- 凭据通过子进程标准输入传递，不写入作业、报告、命令行或环境文件。子进程日志不进入网页；管理操作写审计，仅记录 ID。
- 相同案例的连续轮次会保留各候选自己已经确认的捕获回复。因此后续历史差异是候选导致的结果；对严格同历史单轮比较应将历史放入 `seed.session_history`，仅留一个触发事件。

## API

管理员认证与 CSRF 沿用现有管理台。`build_quality_router(runtime=runtime)` 注册以下入口：

- `GET /api/v2/quality`：案例、作业、可用 Provider、评分维度。
- `POST /cases`：`title`、`split`（`development` / `holdout`）、`case`、`redact_confirmed: true`。
- `POST /preview`：`case_ids`、`provider_id`、显式 `request_budget`。
- `POST /jobs`：预览参数加 `confirmed: true`；同一服务一次运行一个作业。
- `GET /jobs/{id}`：安全状态、进度、盲评候选、已评分 ID；不返回版本映射。
- `POST /jobs/{id}/scores`：`ballot_id`、`winner`（候选 ID / `tie` / `both_bad`）、五维 `dimensions`（1–5）与 `reason`。
- `GET /jobs/{id}/report`：全部盲评完成后揭盲，返回原始结果与汇总。
- `POST /jobs/{id}/cancel`：停止作业。

SSE 事件 `quality.job.updated` 只包含作业 ID、状态与完成数量。案例和报告保存在插件数据目录下的 `quality_lab`，应按聊天资料管理访问与备份。

复用依据：实际核对 [Promptfoo Python Provider 文档](https://www.promptfoo.dev/docs/providers/python/)（2026-10-10）中的 `call_api` 接口，现有离线入口继续兼容该协议。网页不额外启动 Promptfoo 常驻服务或评分模型。
